# เอกสารออกแบบฐานข้อมูลใหม่ — เกณฑ์กิจกรรมพัฒนานิสิต (รองรับหลายปี/หลายกลุ่ม)

> ร่างเพื่อทบทวนก่อนลงมือ · เป้าหมาย: ให้ระบบรองรับเกณฑ์ที่เปลี่ยนตามปีการศึกษาและกลุ่มนิสิต
> โดยไม่กระทบข้อมูลรุ่นเก่า

## 1. ปัญหาของ DB เดิม
โครงเดิม `hourcategory`(5) / `hoursubcategory`(13) เก็บ `required_hours` ค่าเดียวใช้ร่วมทุกปี
จึงรองรับไม่ได้เมื่อ:
- เกณฑ์เปลี่ยนรายปี (แบบเก่า vs โครงสร้าง 2567)
- เกณฑ์ต่างกันตามกลุ่มนิสิต (ปกติ 60 ชม. / ต่อเนื่อง-พิเศษ 30 ชม.)
- มีชั้น Talent/PLO + แยกบังคับ/เลือก + กฎเลือกพิเศษ
- ปี 4 ยังใช้เกณฑ์เก่าพร้อมกับปี 1-3 ที่ใช้ 2567

## 2. แนวคิดหลัก — "ชุดเกณฑ์" (Criteria Set) แบบมีเวอร์ชัน
แยก "นิยามเกณฑ์" ออกจาก "ข้อมูลการเข้าร่วมจริง" และผูกนิสิตเข้ากับชุดเกณฑ์ตามรุ่น+กลุ่ม

## 3. ตารางใหม่ที่เสนอ

### 3.1 `criteria_set` — ชุดเกณฑ์ (หนึ่งชุดต่อ ปีหลักสูตร × กลุ่มนิสิต)
| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| id | PK | |
| code | VARCHAR UNIQUE | เช่น `2567-regular`, `2567-continuing`, `legacy-2566` |
| academic_year | INT | ปีหลักสูตร (2567 / 2566) |
| program_type | ENUM | `regular` (ปกติ) / `continuing` (ต่อเนื่อง-ภาคพิเศษ 2 ปี) |
| name | VARCHAR | ชื่ออ่านง่าย |
| total_required_hours | FLOAT | 60 / 30 |
| counting_rule | ENUM | `total_per_unit` / `min_per_requirement` ← ปิด open item กฎนับ (ตั้งต่อชุดได้) |
| is_active | BOOL | |
| effective_from / to | DATE | ช่วงที่ใช้ |

### 3.2 `talent` — กลุ่ม Talent/PLO (เฉพาะโครง 2567)
| id | criteria_set_id (FK) | code | name | plo | order |
เช่น Glocal/PLO1, Communication/PLO2, Social Innovation/PLO3 · ชุดเก่าอาจมี talent เดียว (default) หรือ null

### 3.3 `learning_unit` — หน่วยการเรียนรู้ (อ้างอิงคงที่ 5 หน่วย)
| id | code | name |
1 พัฒนาทักษะชีวิต · 2 TSU รับใช้สังคม · 3 ศิลปวัฒนธรรมอาเซียน · 4 พัฒนาคุณธรรมและวินัย · 5 ใฝ่เรียนรู้ตลอดชีวิต
(taxonomy คงที่ ใช้ร่วมทุกชุดเกณฑ์ — ทั้งเก่าและ 2567 อ้างหน่วยเดียวกัน)

### 3.4 `requirement` — รายการเกณฑ์ย่อย (leaf ที่กิจกรรมผูก) — แทน hoursubcategory เดิม
| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| id | PK | |
| criteria_set_id | FK | อยู่ชุดไหน |
| talent_id | FK nullable | กลุ่ม Talent (โครง 2567) |
| learning_unit_id | FK | หน่วยการเรียนรู้ |
| name | VARCHAR | เช่น "กิจกรรมกลุ่ม TSU Good", "ทักษะการใช้ภาษาสื่อสาร" |
| is_mandatory | BOOL | บังคับ / เลือกเข้าร่วม |
| required_hours | FLOAT | ชั่วโมงของรายการนี้ |
| min_activities | INT null | ถ้ามีเงื่อนไข "อย่างน้อย N กิจกรรม" |
| rule_note | TEXT null | กฎพิเศษที่ยังไม่ structured (เช่น เลือก 3 จาก 5 / รวม ≥16) |
| organizer | VARCHAR null | หน่วยงานจัดกิจกรรม |

### 3.5 ปรับ `student`
- เพิ่ม `cohort` (ปีที่เข้า เช่น 2566 จากรหัส 66xxxxxxx) และ `program_type` (regular/continuing)
- เพิ่ม `criteria_set_id` (คำนวณจาก cohort+program_type) เพื่อรู้ว่านิสิตใช้เกณฑ์ชุดไหน

### 3.6 ปรับ `activity`
- เปลี่ยน `subcategory_id` → `requirement_id` (ชี้ requirement ในชุดเกณฑ์ที่ตรงกับปีจัดกิจกรรม)

### 3.7 ปรับ `participation` (กัน historical เพี้ยน)
- คง `hours_earned` (snapshot ชั่วโมง — ดีอยู่แล้ว)
- เพิ่ม snapshot `learning_unit_id` / `requirement_name` ณ เวลาอนุมัติ เพื่อประวัติไม่เปลี่ยนแม้เกณฑ์แก้ทีหลัง

## 4. การคำนวณ "ครบเกณฑ์" ใหม่
`gold_student_hours` เปลี่ยนจากเทียบชุด global → เทียบ `criteria_set` ของนิสิตแต่ละคน
และรองรับ `counting_rule` 2 แบบ (ยอดรวมต่อหน่วย / ขั้นต่ำต่อ requirement)

## 5. แผน Migration
1. สร้าง 5 `learning_unit` คงที่
2. สร้าง `criteria_set`: `legacy-2566` (จากข้อมูลเดิม, 60 ชม.), `2567-regular` (60), `2567-continuing` (30)
3. แปลง hoursubcategory เดิม → requirement ใน `legacy-2566`
4. ใส่ requirement ของ 2567 ตามเอกสาร (Glocal/Communication/Social + บังคับ/เลือก + ชั่วโมง)
5. backfill `student.cohort` จากรหัสนิสิต, `program_type` (ตั้ง default regular), map `criteria_set_id`
6. map `activity.subcategory_id` เดิม → `requirement_id` ใน legacy set
7. เพิ่ม nullable → backfill → NOT NULL (pattern เดิม), DROP+สร้าง gold views ใหม่

## 6. ประเด็นที่ต้องตัดสินใจ/ถามอาจารย์ก่อน
1. **กฎนับชั่วโมง** (open item เดิม) — ยอดรวมต่อหน่วย หรือขั้นต่ำต่อ requirement? ต่างชุดใช้ต่างกันได้ไหม
2. **กฎเลือกพิเศษ** — "เลือก 3 จาก 5", "รวม ≥16 หรือด้านเดียว ≥16" จะบังคับในระบบจริง หรือเก็บเป็นหมายเหตุให้เจ้าหน้าที่ตรวจเอง? (บังคับจริงต้องออกแบบ rule engine เพิ่ม)
3. **กลุ่มนิสิต** — ระบบต้องรองรับ continuing/ภาคพิเศษ ตอนนี้เลย หรือทำ regular ก่อน
4. **นิสิตข้ามรุ่นระหว่างเปลี่ยนเกณฑ์** — ปี 4 ปัจจุบันใช้เก่า ปีถัดไปเลื่อนเป็นอะไร ใครกำหนด cohort→criteria_set

## 7. ขอบเขตงาน
เป็นการแก้ schema แกน (เพิ่ม ~4 ตาราง + แก้ 3 ตาราง + migration + แก้ gold views + logic คำนวณ)
ควรทำ **หลังยืนยันข้อ 6 กับอาจารย์** แล้วค่อยแตกเป็น migration ทีละขั้นให้ Claude Code ทำ + เทสต์

## 8. การแมปรหัสนิสิต → ชุดเกณฑ์ (ยืนยันแล้ว)
```
ปีที่เข้า (พ.ศ.) = 2500 + รหัสนิสิต 2 ตัวแรก
รหัส 67 ขึ้นไป (เข้า ≥ 2567) → ชุดเกณฑ์ "2567"
รหัส 66 ลงไป (เข้า ≤ 2566) → ชุดเกณฑ์ "เก่า"
```
backfill `student.cohort` + `criteria_set_id` จากรหัสได้อัตโนมัติ ไม่ต้องกรอกมือ
(program_type ปกติ/ต่อเนื่อง ยังต้องมีแหล่งแยก — ตอนนี้ default = ปกติ)

**อัปเดต (เฟส 1 ของการจัดการชุดเกณฑ์):** กติกาข้างบนไม่ได้ฝังอยู่ในโค้ดแล้ว แต่ละชุด
บอกเองว่าเริ่มใช้รุ่นไหนผ่าน `criteria_set.effective_from_cohort` แล้ว `app/criteria.py`
เลือก *ชุดที่ค่านั้นสูงสุดแต่ยังไม่เกินรุ่นของนิสิต* (ภายใน program_type เดียวกัน) เหมือนขั้นบันได:

| ชุด | effective_from_cohort | รุ่นที่ตกขั้นนี้ |
|---|---|---|
| `legacy-2566` | 0 | 2566 ลงไป |
| `2567-regular` | 2567 | 2567–2569 |

เพิ่มชุดของรุ่น 2570 = เพิ่มแถวเดียว นิสิตรหัส 70 ขึ้นไปย้ายไปเองโดยไม่ต้องแก้โปรแกรม
ผลลัพธ์ของสองรุ่นที่มีอยู่ยังเหมือนเดิมเป๊ะ (ยืนยันด้วย `backend/check_resolver_parity.py`)

`criteria_set.is_system` แยก "เกณฑ์ทางการที่ seed ไว้" (seed เขียนทับได้) ออกจาก
"ชุดที่ผู้ดูแลสร้างเอง" (seed ต้องไม่แตะ ไม่งั้นงานที่คนทำไว้หายตอนคอนเทนเนอร์บูต)

## 9. ข้อมูลชุดเกณฑ์ 2567 — หลักสูตรปกติ (60 ชม.) — พร้อม seed
บังคับรวม 12 · เลือกรวม 48 · counting: ทำตามชั่วโมงที่ระบุต่อรายการ (บังคับต้องครบทุกตัว)

**Talent 1 — TSU Glocal Talent (PLO 1) · รวม 30 ชม.**
| รายการ | บังคับ/เลือก | ชม. | หน่วยการเรียนรู้ |
|---|---|---:|---|
| กิจกรรมปฐมนิเทศนิสิต | บังคับ | 4 | 5 ใฝ่เรียนรู้ตลอดชีวิต |
| กิจกรรมเกี่ยวกับการใช้ชีวิตในมหาวิทยาลัย | บังคับ | 4 | 4 พัฒนาคุณธรรมและวินัย |
| การคิด วิจารณญาณ และการแก้ปัญหา | เลือก | 3 | 1 พัฒนาทักษะชีวิต |
| การบริหารจัดการตนเอง | เลือก | 3 | 1 พัฒนาทักษะชีวิต |
| การทำงานร่วมกับผู้อื่น | เลือก | 3 | 1 พัฒนาทักษะชีวิต |
| ความรู้ ความเข้าใจ และการใช้เทคโนโลยีดิจิทัล | เลือก | 3 | 5 ใฝ่เรียนรู้ตลอดชีวิต |
| กลุ่ม TSU Good (จิตอาสา/บำเพ็ญประโยชน์/สิ่งแวดล้อม) | เลือก | 10 | 2 TSU รับใช้สังคม |

**Talent 2 — TSU Communication Talent (PLO 2) · รวม 10 ชม.**

**Talent 3 — TSU Social Innovation/Entrepreneurship (PLO 3) · รวม 20 ชม.**
| รายการ | บังคับ/เลือก | ชม. | หน่วย |

**สรุป regular:** 8 + 22 + 10 + 4 + 16 = 60 ชม. (บังคับ 12 / เลือก 48)
